## ✅ Лобби: запуск с урезанным числом игроков (без ботов)

**Реализовано.** Было записано здесь как отложенное — при дальнейшем обсуждении нашёлся более простой путь, чем два варианта, изначально рассмотренных ниже.

**Что сделано:** матч теперь создаётся не в момент создания лобби, а **только при нажатии «Начать»** — с финальным списком тех, кто реально подключился к тому моменту (плюс боты, если организатор их выбрал). До старта подключившийся игрок видит не игровой экран, а простую отдельную страницу ожидания (`lobby-wait.html`), которая ничего не знает про протокол игры — просто опрашивает статус по обычному HTTP раз в 1.5 секунды и сама перенаправляет на настоящую игру, как только организатор жмёт «Начать».

Именно это и решило исходную развилку двух вариантов ниже: раз матча не существует до старта, «меньше игроков без ботов» перестаёт быть отдельным случаем — это просто то, что происходит по умолчанию, если организатор не попросил ботов на пустые места (`dropUnfilledSeats: true` в `POST /api/lobbies/:id/start`).

<details>
<summary>Исходная запись (для истории — почему казалось сложнее)</summary>

Проверено: `ServerHost.createMatch({id, ...})` не умеет пересоздавать матч под тем же `id` — список игроков фиксируется раз и навсегда. Рассматривались два пути:

- **Вариант A** — отложить создание матча до кнопки «Начать» (в итоге выбран, см. выше). Ожидалась сложность: игрокам нечему синхронизироваться до старта. Решилось не доработкой протокола ожидания, а тем, что ожидающий вообще не подключается к игре — только к простой статус-странице.
- **Вариант B** — новый `matchId` при уменьшении числа мест, с живой миграцией уже открытой вкладки игрока. Не понадобился.

## Упрощение UI страницы создания игры

После первой реализации лобби появился реальный отзыв: «опять всё сложно и перепутано». Разобрали по пунктам, согласился почти со всем без возражений — план оказался чище того, что было построено:

- **«Играть» в лаунчере теперь сразу ведёт в создание игры** для выбранной там игры — убрана отдельная кнопка «Создать матч». Она решала несуществующую проблему: реальный игрок никогда не видит каталог лаунчера, только организатор на своей же машине.
- **Убран переключатель «Обычный матч / Лобби»** и вся форма с именованными игроками — лобби осталось единственным путём через интерфейс. Один экран: число игроков → сразу один QR-код.
- **Per-seat выбор стратегии бота на каждое место заменён на две кнопки** — «Начать с подключившимися» / «Добавить ботов и начать» (с случайной стратегией на каждое пустое место, не одной на все).
- **Убрана галочка «разрешить зрителей»** — теперь всегда `public` по умолчанию.
- **Добавлен живой счётчик на странице ожидания** («Подключилось: X из Y») — раньше его не было вообще.

Серверная модель (лобби, короткие ссылки, `dropUnfilledSeats`) не менялась — упрощение было чисто на уровне интерфейса.
