## P0-1 — `clone()` (`structuredClone`) падает на циклических ссылках

**Статус: фактически неверно** — та же ошибка, что и в параллельном аудите движка (`audit.md`).

`structuredClone()` нативно и штатно обрабатывает циклические ссылки (проверено напрямую: `const c={}; c.self=c; structuredClone(c)` — работает корректно). Это одно из ключевых отличий от `JSON.stringify()`. Реально `structuredClone()` бросает исключение на функциях и Symbol, не на циклах — и в состояние игры (`Map`/`Set`, координаты, числа) функции/Symbol попасть не могут через нормальный игровой поток. Исправление не внедрено — предпосылка неверна.

---

## P0-2 — `legacyRandom.shuffle` мутирует исходный массив, ломая детерминизм

**Статус: фактически неверно** в части «ломает детерминизм» — заявление концептуально ошибочно.

Проверил все реальные вызовы `shuffle()` в `legacy/game.cjs` (генерация типов объектов сектора, коллапс тайлов) — оба работают с **временными, локальными массивами**, на которые больше никто не ссылается ни до, ни после вызова. Но важнее: **мутация массива на месте не влияет на детерминизм сама по себе**. Детерминизм обеспечивается seeded RNG — при одинаковом seed и одинаковом входном массиве результат перемешивания (порядок элементов) будет одинаковым **независимо** от того, мутирует ли функция исходный массив или возвращает новый. Мутация vs копирование — это вопрос aliasing/побочных эффектов (может ли кто-то ещё держащий ссылку на исходный массив неожиданно увидеть изменения), не вопрос воспроизводимости результата. В данном случае aliasing-риска тоже нет, поскольку массивы временные. Изменение не внедрено.

## P0-4 — утечка `PRIVATE_EVENTS` в публичные события

**Статус: фактически неверно** — механизм фильтрации уже существует и уже протестирован.

Нашёл прямо в коде: функция `emit()` (внутри `buildContext`) **уже** реализует аудиторию для событий из `PRIVATE_EVENTS`:
```js
emit(type, payload = {}, audience = null) {
  ...
  else if (PRIVATE_EVENTS.has(type)) {
    const actor = payload?.player || payload?.owner || action?.actor;
    if (actor != null) evt.audience = [String(actor)];
  }
  ...
}
```
И протокол-слой (`packages/protocol/src/visibility.js`'s `filterEventsForViewerWithPolicy`) **уже** проверяет это поле при построении сообщения для каждого конкретного получателя (`event.audience` — массив разрешённых id; отсутствие поля = публичное событие). Этот механизм уже покрыт реальными тестами из более раннего аудита (`packages/protocol/test/protocol.test.js` — «a private-to-player event is not accidentally exposed to a tv-role viewer»). Заявление о том, что «нет механизма, который бы гарантированно фильтровал» — не подтвердилось: механизм есть, работает, протестирован. Изменение не внедрено.
