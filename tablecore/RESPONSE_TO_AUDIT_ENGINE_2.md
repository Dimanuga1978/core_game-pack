# Ответ на технический аудит: @tablecore/core и @tablecore/game-api

Отвечаю на `audit.md`. Каждое заявление проверялось напрямую (эмпирические тесты против реального кода), а не принималось на веру и не отклонялось с ходу — как заявления, подтвердившиеся, так и не подтвердившиеся, ниже с конкретными командами/результатами проверки.

## Методология

Полный набор тестов прогонялся дважды с нуля (чистая установка из архива) после всех изменений: **554/554, 0 падений**.

## P0-1 — `actor: null` роняет матч

**Статус: не подтвердилось.**

Протестировал напрямую:
```js
runAction({ game: gridDuel, state, action: { type:'MOVE', actor: null, direction:'E' } })
→ { ok:false, error:{ code:'ILLEGAL_ACTION' } }
```
Никакого краха. `getLegalActions(state, null)` для `gridDuel` корректно возвращает `[]` (простое сравнение `null !== state.activePlayer`), не разыменовывает `null` нигде. Заявленный сценарий («`getLegalActions` упадёт») зависит от **конкретной реализации конкретной игры**, а не является универсальной уязвимостью движка — движок сам по себе не гарантирует и не может гарантировать, что ЛЮБАЯ третья игра корректно обработает `null` без дополнительной проверки в своём собственном коде. Это не отменяет ценность общей рекомендации (валидация формата `actor` на уровне движка была бы полезной defense-in-depth мерой), но формулировка «DoS-уязвимость, кладёт матч» не подтвердилась эмпирически.

## P0-2 — `structuredClone(action)` падает на циклических ссылках

**Статус: фактически неверно.**

```js
const circular = { a: 1 }; circular.self = circular;
structuredClone(circular) // → работает корректно, cloned.self === cloned
```

`structuredClone()` **нативно и штатно обрабатывает циклические ссылки** — это прямо в спецификации (HTML Structured Clone Algorithm) и одно из ключевых отличий от `JSON.stringify()`, которая действительно падает на циклах. Реально `structuredClone()` бросает исключение на **функциях и Symbol** (проверено: `DOMException: () => {} could not be cloned`), не на циклах. Учитывая, что `action` в реальном пути всегда приходит из `JSON.parse()` (WS-сообщение) — JSON физически не может представить функцию или Symbol, значит этот теоретический риск и через сеть недостижим. Исправление не внедрено — оно решало бы не существующую проблему.

## P0-3 — нет валидации длины/символов `action.type`

**Статус: код подтверждён, но конкретный риск (ReDoS/память) не продемонстрирован**, а не гипотетически описан. Не стал вносить изменение без конкретного, воспроизведённого сценария причинения вреда — добавление произвольных ограничений «на всякий случай» без измеренной необходимости не в духе того, как мы разрабатывали остальную часть движка (каждое ограничение в кодовой базе, включая недавно введённые `MATCH_ID_RE`/`PLAYER_ID_RE`, добавлялось по факту найденной конкретной уязвимости, не заранее).

## P0-4/5 — `seed` утекает через `createInitialState()`/`context`

**Статус: подтверждено частично — примитив был избыточно permissive, но не эксплуатировался ни в одной из пяти реальных игр. Исправлено.**

Проверил все пять реальных игр поле-в-поле: ни одна не кладёт `seed` в возвращаемое состояние (`grid-duel`/`coin-race`/`phase-quest` его вообще не используют; `sector-expedition` использует только для вычисления, кто ходит первым, не сохраняет; `last-sector`'s `cfg` строится через явное перечисление полей, `seed` там нет). Активной утечки через существующие игры не нашёл.

Но сам механизм передачи был структурно небезопасен: `match.options` (сохраняющее исходные опции вызывающей стороны как есть) спредилось в `createInitialState()` **без** вычистки зарезервированных полей, и `context.seed` передавался в `dispatchMatchAction()` — оба нигде не читались реально, но ничто не мешало будущему автору игры случайно положить их в возвращаемое состояние/событие.

**Исправлено оба места**:
- `context.seed` полностью убран из `dispatchMatchAction()` — только `context.rng` (реально используемый способ получить случайность).
- `match.options` теперь вычищается той же функцией, что уже вычищала `context` (`stripReservedContextFields`), перед спредом в `createInitialState()`.

Подтверждено вживую: матч, созданный с `options: {seed: 424242}`, — итоговое состояние не содержит буквального значения `424242` нигде. 2 новых теста, включая прямую проверку через игру, отражающую полученные `options`/`context`.

## P1-6 — `match.id` через `Date.now()` ломает replay

**Статус: фактически неверно.**

`packages/core/src/replay/replay.js` **не использует `match.id` вообще** — только `pack.manifest.id` (id **игры**, не матча). Реконструкция партии идёт через отдельно записанный лог действий (`replay.actions`) и seed, оба детерминированы независимо от того, как сгенерирован `match.id`. `match.id` — это просто ключ поиска (как первичный ключ в базе данных), не участвующий в игровой логике или воспроизведении. Изменение не внедрено — предпосылка неверна.

## P2-11/13 — лимит на количество событий / точность `SeededRng.int()`

**Лимит на события за одно действие** — не проверял детально, откладываю.

**`SeededRng.int()` — подтверждено и исправлено.** `max - min + 1` действительно может превысить `Number.MAX_SAFE_INTEGER` для достаточно экстремального диапазона, теряя точность IEEE-754. Ни одна реальная игра не запрашивает диапазон даже близко к этому (самый большой реальный случай — перемешивание тайлов доски `last-sector`, ограниченное `MAX_GRID_DIMENSION`) — это защитная мера на будущее/сторонние паки, не исправление достижимого сегодня сбоя. Добавлена явная проверка, бросающая `RangeError` вместо молчаливой потери точности. 3 новых теста.

---

## P2-12 — `MAX_RECENT_MATCH_EVENTS = 100` мало для отладки

**Статус: основано на неверном понимании назначения поля.** Это поле изначально (до предыдущего раунда исправлений) было write-only — никем не читалось для диагностики вообще, что и было находкой более раннего аудита (unbounded memory growth без реальной пользы). Оно никогда не задумывалось как инструмент отладки конкретного хода в партии — это не журнал аудита, а просто ограниченное недавнее окно. Изменение не внедрено.

## Итог

3 находки подтвердились как реальные (пусть и не эксплуатируемые сегодня) улучшения и исправлены: убран `context.seed`, вычищен `match.options` перед спредом, добавлена защита `SeededRng.int()` от потери точности. Большинство P0/P1-заявлений (`actor: null`, `structuredClone` на циклах, `match.id` через `Date.now()`, утечка seed как активная уязвимость) при прямой проверке **не подтвердились** — либо фактически неверны (структурированное клонирование циклов, использование `match.id` в replay), либо описывают то, что зависит от конкретной реализации третьей игры, а не является уязвимостью самого движка.

5 новых тестов, 554/554 всего, дважды с нуля.
